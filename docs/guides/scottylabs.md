# ScottyLabs projects

Remote inspection resolves the latest canonical revision through Forgejo's API.
You do not need clones of governance, infrastructure, documentation, or changelog.

## Find ownership and access

```sh
collar project view ScottyLabs/collar
collar project select
collar governance project list
collar governance project view collar
collar governance service-access -R ScottyLabs/collar
```

Project views show the owning team, inherited leads and members, enabled
features, and secret namespace. The namespace is the governance slug, which can
differ from the repository name. A team-owned repository may have no namespace.

`project select` is a terminal picker that prints the selected project's context.
It does not save a repository selection for later commands.

These are declarations, not proof that access has been provisioned. Repository
settings, membership, and feature changes belong in governance's review and
Atlantis workflow.

## Read documentation

```sh
collar docs list
collar docs search secrets
collar docs view onboarding/contributing
collar docs list --service kennel
collar docs search preview --service kennel
```

The default service is the ScottyLabs organization guides. `--service` also
accepts `kennel`, `infrastructure`, and `governance`. Use `list` to find topic
names before calling `view`; `search` matches a literal phrase.

## Read platform changes

```sh
collar changelog view kennel
collar changelog view governance
collar changelog updates
collar changelog update 17
```

Repository summaries are generated by the changelog repository. Numbered updates
are announcements for tech leads, listed newest first. Authoring and publication
remain in that repository's workflow.

## Inspect infrastructure

```sh
collar infra hosts
collar infra service kennel
collar infra check
collar infra build infra-01
collar infra atlantis-config
```

`hosts` and `service` locate configuration sources; they do not evaluate Nix or
check live services. Check and build commands evaluate the complete remote flake
pinned to the inspected revision. They require Nix, but no manually maintained
infrastructure clone. `build` creates a system closure locally without deploying
it. Atlantis remains responsible for infrastructure plans and applies.

## Work offline

Add `--offline` to discovery commands to read the last verified snapshot. It
makes no source API requests and fails if the snapshot is absent or corrupt.
Online commands refresh explicitly and do not silently reuse stale data after a
network error.

Nix operations use `--offline-source`, which also forwards Nix's `--offline`
flag. Nix must already have the required inputs cached.

An optional `--checkout PATH` inspects local working changes. It is an override
for maintainers, not a prerequisite for normal use. Output identifies the
source revision or local working tree.

For current service configuration, consult the
[governance repository](https://git.cmu.dev/ScottyLabs/governance) and
[Kennel feature guide](https://docs.kennel.scottylabs.org/guides/features.html).
